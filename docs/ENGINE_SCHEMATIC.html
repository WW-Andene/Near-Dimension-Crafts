Does mapping this out actually help?

Yes — for two different reasons. First, as a reference: once it exists you can point at any lag report or feature request and immediately know which layer and file owns it, instead of re-deriving the dependency graph from scratch each time.

Second, and more concretely: building it methodically is exactly how the SlamLite full-resolution bug and the three unthrottled Bitmap-reallocation sites got found this session — walking every component forces you to check "does this one follow the same discipline as its siblings," and inconsistencies like that don't show up any other way. The tree below is the result of that same pass, laid out so the next one is easier.

Foundation — util

no dependencies

Rate-control and budgeting primitives shared by every layer above. Nothing here touches Android APIs or does domain work — it only decides how often the domain work above is allowed to run.

utiladaptive inference-rate governors
FrameThrottlerGates MediaPipe dispatch (shouldInfer()); adapts inferEvery 1–4× from measured dispatch time and hand-motion magnitude. §17.4: fixed a feedback bug where idle-doubling contaminated the true GPU-rate signal — now tracked via a separate gpuRate field.
ModelBudgetManagerPer-model EMA (hand/body/face) against a 25ms frame budget; sheds body detection first, then face, recovers one step per 30 frames once load drops below 70% of budget.
DepthChannelBudgetSame shed/recover shape as ModelBudgetManager, scoped to Core-layer channels (SLAM, DA2). Audited this session for the FrameThrottler-class bug — its EMA tracking is structurally independent of shed state, none found.

Core

camera · depth

Sensor pixels in, depth/spatial signal out. No semantic labels — nothing here knows what a "hand" or "joint" is, only where surfaces are in space and how confident that estimate is.

camerasensor acquisition & frame prep
CameraControllerOwns the Camera2/CameraX session lifecycle — open, configure, tear down.
CameraFrameProviderConverts YUV → RGBA and handles rotation via a pre-allocated multi-bitmap pool (rotatedBitmapPool, outputBitmapPool) — the reference example for the reuse-not-reallocate pattern applied elsewhere this session.
GrayscaleCameraStandalone 320×240 luma-only capture path used where SfM/Photometric need raw Y-plane data without a second camera session.
BitmapGrayscaleShimFeeds CameraFrameProvider's existing Bitmap stream into SfM/Photometric as 320×240 luma FloatArrays, avoiding a second concurrent camera session. §17.6: was reallocating a Bitmap+Matrix on every uncapped camera frame — now a persistent Bitmap+Canvas pair, redrawn in place.
LowLightEnhancerDark-gated (hysteresis) CLAHE/gamma/unsharp/hot-pixel-suppression/temporal-EMA pipeline, active only below a luminance threshold. §17.6: meanLuminance()'s per-frame sample bitmap and enhance()'s output (double-buffered, since MediaPipe's async detector may still be reading the previous frame) both moved off per-call allocation.
depth12-channel depth fusion & 3D reconstruction
SpatialLayerTop-level orchestrator for every depth/spatial subsystem below; entry point called once per camera frame from the Translation layer.
FusedDepthSourceOwns processAuxSources() — runs DA2, DRASL/JBU, and (when reconstruction is active) RS-stereo, PSP, stereo capture, flare/moiré detection.
CrossChannelArbiterFuses all 12 depth channels per depth-block using Gaussian z-score gating against per-channel baseWeights priors — the evidentiary source for the channel-ranking table below.
ArCoreDepthSourceChannel CH_BASE — ARCore's own depth API (ToF/motion-stereo hybrid where hardware supports it). Highest-trust prior.
StructuredLightDepthSourceChannel CH_SL — active structured-light pattern projection/decode, where a projector is available.
PhotometricDepthSourceChannel CH_PSP — shape-from-shading using varying light direction across frames.
SfMDepthSourceChannel CH_DVEL — structure-from-motion using tracked feature displacement across frames (device-velocity-derived parallax).
DepthAnythingSourceChannel CH_DA2 — ONNX Runtime CNN (DA2 ViT, fixed 518×518 input), monocular dense depth. Heaviest single compute cost of any channel; always-on per explicit product decision.
StereoDepthSourceChannel CH_STEREO — dual-camera stereo disparity where a second lens is available. extractBitmapLuma() is the original persistent-Bitmap reuse pattern later copied into BitmapGrayscaleShim and SlamLite.
RollingShutterStereoChannel CH_RS — exploits rolling-shutter skew between frames as a synthetic stereo baseline on single-camera devices.
PhaseShiftingProfilometryChannel CH_PSP-adjacent — phase-shift pattern analysis for fine surface detail during active scanning.
FlareDetectorChannel CH_FLARE — detects lens-flare-corrupted regions to down-weight unreliable depth blocks rather than estimate depth itself.
MoireDetectorChannel CH_MOIRE — detects moiré interference patterns (screen-capture artifacts) to down-weight affected blocks; same consistency-guard role as FlareDetector.
SlamLiteAlways-on lightweight visual SLAM — Harris corner detection + pyramidal Lucas-Kanade optical flow — for metric pose/motion grounding, not depth per block. §17.5: was the one always-on channel still processing at full camera resolution; now downsamples to 320px width with a compensating scale factor so metric output is unchanged. §17.6: its downsample bitmap also moved to persistent-Bitmap reuse.
SurfaceNormalsDerives per-block surface normals from the fused depth map for lighting and mesh-quality use downstream.
AmbientOcclusionScreen-space AO term computed from fused depth, consumed by the renderer — not a depth source itself.
PlaneFitterFits dominant planes (floor, walls) from the point cloud for scan alignment and room-map anchoring.
VoxelGridRoom map — persistent 5mm-cell spatially-deduplicated point-cloud accumulator, opt-in. Pure downstream consumer of already-fused depth; contributes nothing back to depth accuracy.
TSDFVolumeTruncated signed-distance-field volume accumulated during a scan, the intermediate representation surfaces are extracted from.
DepthCarverConverts hand landmarks to world-space geometry (landmarksToWorld) to carve/refine the mesh during scanning — a data-type dependency on tracking's landmark struct, not a behavioral one.
MarchingCubesExtracts a triangle mesh surface from the TSDF volume at scan-export time.
HandSegmentationMaskBuilds a hull from hand landmarks to mask the point cloud to hand-only geometry during hand scans.

Translation

tracking · mocap · scanner

Camera frame → semantic keypoints (MediaPipe landmarks) → structured motion (joint quaternions) → structured geometry (scanned mesh). This is where raw signal first becomes "a hand" or "a pose."

trackingMediaPipe landmark detection & filtering
HandTrackerManager / HandTrackerRuns MediaPipe hand landmarker (21 points/hand); owns GPU→NNAPI→CPU delegate fallback selection.
BodyPipelineRuns MediaPipe pose landmarker (33 points), gated by ModelBudgetManager's shed/recover decision.
FacePipelineRuns MediaPipe face landmarker (478 points), gated the same way as BodyPipeline.
HandPipelinePost-processes raw hand landmarker output before it reaches retargeting/gesture code.
OcclusionEngineResolves self-occlusion between tracked hand/body segments using depth ordering.
OneEuroFilterPer-landmark low-pass filter tuned to suppress jitter without adding perceptible lag.
TemporalDepthFusionBlends this frame's Core-layer depth at each landmark with recent history for a stable per-joint depth estimate.
SegmentLengthConstraintClamps bone-segment lengths to plausible human proportions to reject depth-noise-induced limb stretching.
GestureClassifier / CompositeGestureClassifierClassifies static/dynamic hand gestures from landmark geometry.
LandmarkUtilsShared coordinate-space and geometry helpers used across the tracking pipelines.
mocapkeypoints → joint motion & network streaming
BoneRetargeterMaps hand landmarks onto a target skeleton's bone rotations.
BodyRetargeterSame mapping for full-body pose landmarks → skeleton joint quaternions.
BiomechanicalConstraintFilterClamps retargeted joint rotations to anatomically valid ranges.
QuaternionEmaFilterSmooths joint-rotation output over time via exponential moving average.
OscStreamer / OscReceiver / OscSchemaAddressesSends/receives VMC-compatible OSC packets for VTuber/mocap software interop; address schema kept centralized after rPPG's dead sender/address pair was deleted this session.
MotionRecorderRecords a motion-capture session to disk for later export.
VrmBlendShapeParserReads VRM avatar blend-shape definitions for face-tracking output mapping.
AssetLoader / BundledAssetGeneratorLoads a GLB/VRM puppet asset from URI/path/bundle; generates a fallback default puppet when the user has none.
LiveMeshDeformerDeforms a loaded mesh in real time to follow retargeted skeleton motion.
scannercustom 3D mesh capture, in place of an uploaded asset
ScannerDrives the guided multi-pose capture state machine (PREFLIGHT → COUNTDOWN → CAPTURING → PROCESSING → DONE/FAILED) that turns a real hand or object into a usable mesh without any pre-made asset.
FreeformScannerUnguided continuous-capture alternative to the fixed 8-pose sequence.
ScanPosesDefines the fixed pose sequence and per-pose capture targets.
CLAHEAnalyzerContrast-limited adaptive histogram equalization for scan-frame quality, gated to scanActive only.
QualityEngineScores captured frames/poses for reconstruction usability, drives retry prompts.
HandBiometrics / JointRomMeasures hand dimensions and joint range-of-motion from scan data for a personalized rig.
ManoShapeFitterFits a parametric hand-shape model (MANO-style) to the scanned point cloud.
PersonalModelStorePersists the fitted personal hand/body model between sessions.

Application

render · export · app

Structured motion/geometry → pixels on screen, files on disk, packets on the network. Nothing below this line feeds back into tracking or depth — it's pure output.

renderOpenGL scene composition
ARRendererTop-level GL scene composer — orders and draws every renderer below into one frame.
HandRenderer / BodySkeletonRenderer / FaceSkeletonRendererDraw tracked skeletons/landmarks as debug or stylized overlays.
DepthMeshRenderer / DepthCloudRenderer / PointCloudRendererVisualize the fused depth signal — as a solid mesh, colored point cloud, or sparse points respectively.
LiveMeshRendererDraws the deforming puppet/avatar mesh driven by mocap output.
CameraPassthroughRendererDraws the raw camera feed as the AR background layer.
ModelViewerRendererStandalone GLB preview renderer used by scan-result review and asset picking.
HandMeshBuilderBuilds renderable GL geometry from hand landmark/depth data each frame.
LightingModelShared lighting parameters (direction, ambient term from AmbientOcclusion) applied across renderers.
ShaderProgramsCompiles and caches the GLSL programs every renderer above draws with.
exportwriting scan results to disk
GLBExporterSerializes the scanned/carved mesh to a glTF binary (.glb) file.
TextureBakerBakes captured color/lighting onto the exported mesh's UV texture.
PointCloudExporterExports the raw fused point cloud independent of mesh reconstruction.
apporchestration, state, and UI
AppViewModelApp-wide state holder; wires every module above together for the UI layer.
SpatialFrameProducerPer-camera-frame entry point — calls Core depth processing, then FrameThrottler-gated MediaPipe detection, assembles one SpatialFrame.
SpatialFrameRouterFans a produced SpatialFrame out to renderer, OSC streamer, and recorder.
ScanCoordinatorBridges UI scan actions to the Scanner state machine and export pipeline.
AssetManagerTracks the active puppet asset and its DataStore-persisted last-used reference. No current auto-link from a completed scan — loading a fresh scan as the active asset is still a manual two-step action.
RecordingManagerControls start/stop of a MotionRecorder session from the UI.
OscManagerOwns OSC connection lifecycle/config surfaced to the UI.
UI screens / composablesCompose screens — camera view, scan flow, asset picker, settings — presenting the state above.

Reading notes

  • Module → layer assignment is verified against each module's build.gradle dependency declarations, not inferred: camera, depth → Core; tracking, mocap, scanner → Translation; render, export, app → Application; util sits underneath all three with no dependencies of its own.
  • The one cross-layer exception is depth importing tracking.HandLandmarks in DepthCarver and HandSegmentationMask — a data-type dependency (coordinate math on a landmark struct) rather than a behavioral one, so it's left in place rather than moved.
  • Component roles above reflect current, verified source — including every fix landed this session (§17.4 FrameThrottler, §17.5 SlamLite downsample, §17.6 Bitmap reuse) and the rPPG module, fully removed per direct request and absent from this map.
